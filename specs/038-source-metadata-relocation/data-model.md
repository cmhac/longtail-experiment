# Data Model: Source Metadata and Adapter Relocation

## Entity: Source Manifest

- Purpose: Contributor-authored source definition used for discovery, registration, scheduling, onboarding, and source-level metadata ownership.
- Fields:
  - source_key: Stable machine identity for the source.
  - provider_group_key: Provider grouping identity used for scheduling and Dagit grouping.
  - title: Required human-readable source title.
  - description: Required human-readable source description.
  - series_item_keys: One or more operator-facing series trigger identities.
  - canonical_series_keys: One or more canonical dataset identities aligned to series items.
  - ownership_mode: Grouped or split ownership semantics.
  - cron_schedule: Source-owned schedule definition.
  - cadence_label: Human-readable cadence classification.
  - builder: Workflow registration builder reference.
- Validation Rules:
  - source_key, provider_group_key, title, and description must be non-empty.
  - title and description must reject blank or whitespace-only values.
  - series_item_keys and canonical_series_keys must be non-empty and index-aligned.
  - source_key must be unique across all discovered manifests.
  - The manifest must live in the maintained source-adapter package.

## Entity: Persisted Source Profile

- Purpose: Source-level persisted record used by discovery queries and dataset/source relationship ownership.
- Fields:
  - source_profile_id: Internal persistent identifier.
  - source_key: Stable source identity used by runtime and route/API contracts.
  - source_name: Existing source attribution field preserved for compatibility where still needed.
  - source_type: Source classification.
  - title: Human-readable source title for application display.
  - description: Human-readable source description for application display.
  - created_at: Source-profile creation timestamp.
- Validation Rules:
  - source_key, source_type, title, and description must be populated after migration.
  - source_key must be unique and stable across source-title changes.
  - title and description must reflect the latest manifest-owned metadata for that source.

## Entity: Source Persistence Context

- Purpose: Execution-time source metadata context passed from discovered source registration into canonical persistence.
- Fields:
  - source_key: Stable source identity for the executing source.
  - source_title: Manifest-owned human-readable source title.
  - source_description: Manifest-owned human-readable source description.
  - source_type: Source classification persisted with the source profile.
- Validation Rules:
  - The context must be present for persisted writes generated by maintained source adapters.
  - The source_key in execution context must match the registration being run.
  - The title and description in execution context must match the discovered manifest for that source.

## Entity: Source Discovery Summary

- Purpose: Backend and frontend list/detail summary for one discoverable source.
- Fields:
  - id: Stable source identifier exposed through APIs and routes.
  - title: Primary human-readable source label.
  - description: Source summary text available to list/detail screens.
  - dataset_count: Total number of visible datasets for the source.
  - source_type: Optional source classification for secondary context.
- Validation Rules:
  - id, title, and description must be non-empty.
  - id must equal the persisted stable source identity.
  - title must be used as the primary display label in source-related UIs.
  - dataset_count must be zero or greater and align with visible source membership.

## Entity: Source Detail View State

- Purpose: User-facing state for the `/sources/{sourceId}` route after the metadata rollout.
- Fields:
  - source: Source Discovery Summary for the selected source.
  - items: Dataset summaries belonging to that source.
  - render_state: Loaded, empty-datasets, not-found, or error.
  - page_context: Existing page, page-size, and total-count pagination metadata.
- Validation Rules:
  - The selected `source.id` must match the requested route identifier.
  - Loaded state must render source title before child datasets.
  - Empty-datasets state applies only when the source exists and has zero datasets.
  - Not-found and error states must remain distinct.

## Relationships

- One Source Manifest owns one Persisted Source Profile.
- One Persisted Source Profile owns zero or more dataset rows through existing source-to-series relationships.
- One Source Persistence Context is derived from one discovered Source Manifest during workflow execution.
- One Source Discovery Summary is projected from one Persisted Source Profile plus dataset membership counts.
- One Source Detail View State contains exactly one Source Discovery Summary when loaded successfully.
